## What We're Building

A phone-based GPS speedometer that shows **speed over ground (SOG) in knots, averaged over a rolling window** (default 15 min, configurable). Single-screen PWA, offline, no backend, no accounts. You're at the helm with a Pixel and want a big, honest average SOG instead of watching the instantaneous number bounce. That's the whole app.

The "chip log" — a knotted line streamed astern to measure a vessel's speed — is where the **knot** as a unit comes from.

**Single user, single role:** the person at the helm. No auth, no multi-tenancy.

## Stack

- **App:** Single static PWA — `index.html` + `styles.css` + `app.js` + `manifest.webmanifest` + `sw.js` + icons + bundled font. **Vanilla JS, no build step, no framework, no dependencies** (DEC-001).
- **Font:** DM Sans (variable woff2, self-hosted in `fonts/` — bundled so the app is fully offline).
- **Offline:** service worker caches the shell; the app needs **no network at runtime** — only GPS.
- **Platform APIs:** Geolocation (`watchPosition`, high accuracy), Screen Wake Lock, Service Worker, localStorage.
- **Hosting:** static folder on **mill-dev**, served over **HTTPS via Tailscale** (`tailscale serve`, tailnet-only — never `funnel`). HTTPS is non-negotiable: Geolocation, Wake Lock, and Service Workers all require a secure context. See `README.md` § Deployment.
- **Testing:** Node-run logic checks for the math (haversine, average SOG); manual on-device verification for GPS/PWA behavior. No Playwright/pgTAP — there's no server, no DB, no DOM framework.

## Architecture (the whole thing)

```
index.html            single screen: status row · hero average · instant · controls · settings sheet
styles.css            DM Sans, three themes (dark / red night / light) via [data-theme] + CSS vars
app.js                geolocation watch → accuracy gate → rolling buffer → haversine → avg SOG; wake lock; settings
manifest.webmanifest  PWA install metadata (standalone, portrait)
sw.js                 caches the shell; CACHE_VERSION bumped per release
fonts/dm-sans-var.woff2   bundled variable font
icons/                generated by scripts/make-icons.py (pure-stdlib PNG, no deps)
```

### The one algorithm that matters

**Average SOG = (Σ great-circle distance between consecutive accepted fixes in the window) ÷ (t_newest − t_oldest accepted fix in the window).** Then m/s × 1.94384 → knots.

- **Distance-over-time, not mean-of-samples.** Averaging instantaneous speeds over-weights noisy fixes and gaps.
- **Denominator = data span, not fixed window length.** 6 min of fixes in a 15-min window divides by the 6 min you actually have, not 15 — so it reads correct, not low (DEC-005; veto point noted in SPEC).
- **Accuracy gate:** discard any fix with `coords.accuracy` worse than the threshold (default 25 m) before it enters the buffer. Kills stationary scatter.
- **Ignore `coords.speed`** — frequently null/unreliable. Compute from position deltas.
- Instantaneous below ~0.3 kn shows `0.0` (no phantom crawl at anchor).
- Haversine, R = 6,371,000 m.

## Conventions

- **Vanilla, no dependencies.** No npm packages ship to the client. Adding any runtime dependency is a DEC + an `@architect` conversation — it contradicts DEC-001.
- **One screen.** Resist adding views. Everything not on the main screen lives in the settings sheet.
- **Plain functions, `"use strict"`, no transpile.** Target current Chrome on a Pixel; don't polyfill for browsers this will never run on.
- **State is module-level in `app.js`** — small enough that a framework would be ceremony. If it stops being small enough, that's a DEC, not a reflex.
- **Naming:** files `kebab-case`; functions `camelCase`; constants `UPPER_SNAKE`.
- **Numbers are tabular.** Any on-screen number uses `font-variant-numeric: tabular-nums` so digits don't jump.

## Versioning (project)

chiplog **has a `package.json`**, so the shell's `/retro` / `/bump-major` bumps run — but the version surface is **not** `<VersionTag />` (that's a Next.js component — **N/A here**), and there is **no `production` branch**. Instead, a **three-way lockstep**:

- `package.json` carries the SemVer version; **`app.js` `APP_VERSION` and `sw.js` `CACHE_VERSION` mirror it.** The service-worker cache name *must* change per release or the new shell won't invalidate (SPEC § Updates).
- **When you bump the version, update all three** — `package.json`, `APP_VERSION`, `CACHE_VERSION`. Same number, different prefixes.
- `/retro` is the only place bumps happen (patch per merged PR, minor at phase close); `/bump-major` is manual. The version shows in the **settings-sheet footer**, sourced from `APP_VERSION`.
